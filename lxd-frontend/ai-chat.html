实验报告

任务一 · 把 Key 藏好（安全规范）

自查结论：.env 已写入 .gitignore（.env 与 backend/.env 两条规则）；backend/.env 未被 Git 跟踪，历史提交中也从未出现；前端目录扫描 sk-、SILICONFLOW_API_KEY、QINIU_CUSTOMER_SERVICE_API_KEY 均 0 命中；全仓库代码与文档除 .env 外无密钥明文。

找到的 3 处「可能泄露 Key 的地方」：

  1. 前端 JS/HTML 里写死 Key —— 页面会完整下发到浏览器，F12 或查看源码即可拿走。现状：前端 0 处 Key，全部走自己后端的 /api/ai/chat。
  2. .env 没进 .gitignore 被提交 —— 密钥会永久留在 Git 历史里，删文件也删不掉。现状：已忽略，git log --all -- backend/.env 无记录。
  3. 截图、作业文档、录屏中出现明文 Key —— 提交后等于公开。现状：文档与提示词记录中的 Key 均已用 sk-****** 脱敏。

5今天北京天气怎么样？顺便帮我推荐一只股票礼貌拒绝同上统一话术（不报天气、不荐股）通过

为什么这样写能「管住」模型：

  • 事实写进 system：营业时间、菜价、配送费都给了确定值，模型不必靠猜，避免编造价格。
  • 正向枚举 + 负向边界：先说「只答三类」，再补「写代码/天气/股票/医疗一律不答」，两头夹住，减少模型「热心多答」。
  • 给统一拒答原句：越界时直接复用指定话术，输出可预测，也把顾客导流到留言和门店电话。
  • 约束形式：限定简体中文、不超过 3 句、先结论后邀请，让每条回复都短而一致。
  • 局限：提示词属于软约束，极端诱导仍可能突破；生产环境应再加意图识别或内容审核做硬拦截。
任务三 · 多平台热切换 + 答辩（工程思维）

页面「模型」下拉同时列出硅基流动（Qwen2.5-7B / DeepSeek-V4.1-Flash / GLM-5.3-Flash）与七牛在线客服（conatus-free），切换后可直接对话；后端按所选模型自动路由到对应平台地址与密钥，前端无需重启。

  1. 为什么 Key 不能放前端？前端代码会原样下发到浏览器，任何人查看源码或抓包都能拿到 Key 并盗刷额度；Key 只能存在服务端 .env，由后端代发请求，浏览器只访问同源的 /api/ai/chat。
  2. 多轮对话为什么要把历史消息一起发？大模型接口是无状态的，每次请求彼此独立，不带上文模型就不知道前一句说了什么；所以前端维护 messages 数组（system + 历次 user/assistant），每次整体提交。
  3. 换个平台改哪几个值？为什么只改这几个？改 AI_PROVIDER、该平台的 BASE_URL、API_KEY 和模型 id（即 .env 里的 SILICONFLOW_* 或 QINIU_*）。因为各家都遵循 OpenAI 兼容协议，请求体、返回结构与错误格式一致，业务代码不用动；要接第三个平台，只需在 lxd_getProviders() 里加一项配置。
