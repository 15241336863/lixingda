操作手册 · 控制台接入

从登录页，走进
你的环境

这一节只解决一件事：用你的账号进到 separate-viper 这个环境里。 路上会经过一个登录页、一个选择环境页，然后才是你能真正操作的界面。 中间每一步的 URL 怎么变、界面上该点什么、点错了会怎样，都在下面。

环境 separate-viper 套餐 体验版 地域 上海 预计走完 15 分钟
00

先看懂全局：三个“登录”别搞混

这是整篇最容易翻车的地方，先分清再动手。

浏览器打开 tcb.cloud.tencent.com/dev没登录会自动跳到登录页
↓
腾讯云账号登录你是谁 —— 账号级身份
↓
选择环境（select-env）进哪个环境 —— 环境级选择
↓
环境内页：概览 / 身份认证 / 数据库 …到这里才算“进去了”

上面这条链：控制台登录。用的是腾讯云账号，一个账号可以管很多个环境。

你做的应用（网页 / 小程序）
↓
默认登录页 / JS SDK用户名密码、微信、验证码
↓
环境里的「用户管理」表这里是终端用户，不是你的腾讯云账号

下面这条链：应用登录。用的是环境自己的用户体系，和你的腾讯云账号没有任何关系。

两条链的账号互不通用

你在用户管理里建的 administrator，登不进腾讯云控制台；你的腾讯云账号，也登不进那个默认登录页。别把两套当成一套排查。

两个别外发的字符串

envId 是你的环境身份证，写在代码里没问题；但登录页「在线体验」打开的预览链接里带一段 accessCode 临时口令，那是验证身份用的，别截图发群、别贴进文档。

01

第一步：先确认脚下有地

环境过期了，后面每一步都会以“打不开”的形式失败，先花一分钟确认。

开通入口

免费体验版开通页：buy.cloud.tencent.com/CloudBase　（套餐页显示“免费试用 6 个月 / ¥0”，不需要绑付款方式）

1

确认套餐与到期时间

你这个环境是体验版，3000 资源点 / 月，有效期到 2027-05-27 23:59:59，不需要续费也能撑到那时候。还没开通的话，直接从上面的开通页走一遍，全程 0 元。

2

知道体验版的边界

体验版不支持购买资源包、不支持按量付费。资源点用光后能力会被限制，届时要么等月度重置，要么升级套餐。日常登录、建几个用户完全够用。

02

第二步：打开控制台入口

记住这个地址，以后所有操作都从这里进。

浏览器地址栏控制台
https://tcb.cloud.tencent.com/dev

没登录时，页面不会白屏，而是自动跳到一个带 ?_redirect_uri= 的登录地址——跳回来这件事平台已经帮你做好了，不用手动记原地址。

两条入口怎么选

入口适合谁注意
腾讯云账号绝大多数情况。主账号 / 子账号都能登，子账号要单独授权环境权限这是最直接的一条，建议默认走它
微信公众平台账号做小程序、公众号网页，手上有已认证的公众平台账号它不是“微信扫码”，是公众平台那套开发者身份
卡在这一步的常见原因

点登录后反复弹回登录页，多半是浏览器把第三方 Cookie 拦了。换无痕窗口、或放行 tcb.cloud.tencent.com 的 Cookie 再试一次。

03

第三步：在“选择环境”页挑环境

登录成功不等于进了环境，这一步是很多人的卡点。

1

点卡片本身，不是点右上角的“…”

整张卡片就是进入按钮。右上角“…“是环境的重命名、删除等操作，别在那儿找进入。

2

只有一个环境时，也要点这一下

平台不会自动帮你选。停在列表页不点，看起来就像“登录没成功”。

3

要建新环境，走卡片上方「新建环境」

它会跳到购买页。免费体验版就在那里开通，价格 0 元，直达链接：CloudBase 购买页（上海 · PostgreSQL）。

地址栏里的 hash 决定你落在哪

#/select-env 一定停在选择页；#/overview 会直接进这个环境。所以收藏链接时，想一步到位就存带 #/overview 的那条。

04

第四步：进入环境的第一屏

看到这一屏，说明登录这一步彻底完成了。

1

先核对环境名，再动别的

顶部居中的下拉框就是当前环境。有多个环境时，切换环境也在这里，不用退回选择页。

2

左栏是全部能力入口

PostgreSQL、云函数、云存储、身份认证、静态网站托管……后面几步只会用到「身份认证」这一项。

3

右上角「4 个事项」先不用管

那是开通建议（开日志、配 IP 限频、续费活动之类），不影响登录流程。

05

第五步：给应用造一个能登录的人

控制台账号是你，用户表里的人是“你应用的用户”。

这个 administrator 是平台在你首次进入环境时自动建的，注册时间和最后登录时间都落在这几分钟里。它的意义是“控制台管理员在这个环境里的对应身份”，不是给你应用用的业务账号。

1

填三项就够

用户名写英文或拼音（如 reader），昵称随你，密码自己定。邮箱手机号留空不影响登录——因为默认登录方式就是用户名密码。

2

密码就是后面登录页要输的那个

这里设的初始密码，等价于该用户在「默认登录页」上的登录密码。不需要再去别处设。

3

点「确定」，列表立刻多一行

新建成功后，用户状态为“已激活”，可以直接拿去登录。忘了密码就在这里点「详情 → 更多」重置。

06

第六步：决定“怎么登录”

用户建好了，还得决定他们从哪个门进来。

登录方式现在的状态要用它得做什么
用户名密码已启用什么都不用做，建好用户就能登
短信验证码未启用先在登录方式里启用，再配短信服务，用户还得有手机号
邮箱验证码未启用同上，改配邮件服务
匿名登入开关默认关闭打开后无需凭证即可登录，但这批用户不进用户列表
微信小程序登录内置在小程序里用 openId 静默登录，不需要额外开启
社交 / 企业登录全部未启用要先去对应平台建应用、拿 AppID 和密钥
1

只勾「账户密码登录」

勾了几个，登录页上就出现几个入口。短信和邮箱没配服务就勾上，用户点了会失败，不如先不勾。

2

「开启注册」先关着

注册只支持短信验证码和邮箱验证码，而这两种你都没启用。关着更安全：用户只能由你在控制台手动创建。

3

品牌化可以跳过

不填企业名称和 Logo，页面就显示“云开发 CloudBase”。自己看效果完全够。

4

保存后等 10 分钟

页面底部写得很清楚：保存后预计 10 分钟内生效。急着验证就用右下角的「在线体验」，它读的是未保存的配置。

07

第七步：预览真实的登录页

这就是终端用户会看到的那一屏。

1

用刚建的用户试一次

用户名 administrator，密码是建号时那个。登录成功后页面会跳到回调地址，本页就离开了。

2

登录成功在哪验证

回到「用户管理」，看这个用户的最后登录时间有没有更新——这是最直接的证据，比看页面跳转可靠。

3

这个页面的地址不要外传

「在线体验」打开的链接里有临时 accessCode，属于预览态口令，发出去等于把入口一起发了。

08

第八步：把登录接进你自己的应用

可选。只做控制台操作的话，到上一步就可以停。

index.html引入 SDK
<script src="https://static.cloudbase.net/cloudbase-js-sdk/latest/cloudbase.full.js?v=1"></script>
初始化env 换成你自己的
const app = cloudbase.init({
  env: "separate-viper-d0gp2x0l2ccbb03e9", // 环境 ID
  region: "ap-shanghai",               // 不传默认上海
});
window.app = app;
跳转默认登录页一行
// 用户点“去登录”时调用
window.app.auth().toDefaultLoginPage({ redirectUrl: '' });
最容易踩的一条

跳转登录页的域名必须和 redirectUrl 的域名一致，否则登录态跨域共享失败——表现是“登录成功了，但回到页面还是未登录”。本地调试时，两边都指向同一个 localhost 端口。

登录方式JS SDKHTTP API
匿名登录支持支持
用户名密码登录支持支持
短信验证码支持支持
邮箱登录支持支持
小程序 openId 静默登录支持不支持
09

报错速查表：先看现象再改配置

按“你看到什么”来找，不要按“我改了什么”来找。

现象真正的原因怎么解决
一打开就跳登录页没登录，或登录态被浏览器清了正常行为，登一次即可；反复跳转就查第三方 Cookie
登录完仍停在环境列表没点卡片点一下卡片进环境，别停在列表页等
进环境后名字不对选错了环境，或地址里 envId 是旧的用顶部下拉框切回 separate-viper
用户名密码登录是灰的该方式未启用配置 → 登录方式 → 把「用户名密码」打开
登录页提示密码错误初始密码记错用户管理 → 详情 → 更多 → 重置密码
短信 / 邮箱登录点不动方式未启用，且短信邮件服务没配先启用方式，再配服务商；先用用户名密码顶上
登录成功但控制台看不到这个人用的是匿名登录，匿名用户不入库正常现象；要给业务身份就关掉匿名、走密码登录
应用里登录成功、页面仍显示未登录登录页域名与 redirectUrl 不一致，登录态没共享两端同域同端口，再重新登录一次
改了配置没反应配置有约 10 分钟生效延迟用「在线体验」验证，或等 10 分钟再刷新
提示环境不存在 / 权限不足envId 写错，或这个腾讯云账号没被授权该环境核对 envId；主账号给子账号加环境权限
排查顺序

先看地址栏落在哪个 hash（是不是被踢回 login 或 select-env）→ 再看环境名对不对 → 最后才看登录方式和用户。从外往里查，比在表单里反复试快得多。

1 星 · 基础

走一遍并记录 URL

流程理解

从入口进到概览，把地址栏每一次变化抄下来（login 页、select-env、overview）。写出哪一步的 hash 决定了你落在哪一屏。

2 星 · 配置

建一个 reader 用户

账号体系

新建 reader，关掉匿名登入，只保留用户名密码登录，然后用它在默认登录页登录。说明为什么注册开关要保持关闭。

3 星 · 接入

接进页面并现场演示

工程思维

用 JS SDK 在自己页面加一个「去登录页」按钮，登录后回到页面。答辩三问：envId 写在哪、登录态为什么不共享、两套账号体系怎么区分。

说明　本页所有截图取自 separate-viper 环境（体验版，有效期至 2027-05-27）的实际界面，路径与文案以当前控制台版本为准。平台改版后，按钮位置可能变化，但「登录 → 选择环境 → 环境内页」这条链路不会变。
