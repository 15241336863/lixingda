实验报告（内嵌）

任务一 · 把 Key 藏好（安全规范）

自查结论：.env 已写入 .gitignore；backend/.env 未被 Git 跟踪；前端目录扫描 sk-、SILICONFLOW_API_KEY、QINIU_CUSTOMER_SERVICE_API_KEY 均 0 命中。

找到的 3 处「可能泄露 Key 的地方」：

  1. 前端 JS/HTML 里写死 Key —— 页面会完整下发到浏览器，F12 即可拿走。现状：前端 0 处 Key，全部走后端 /api/ai/*。
  2. .env 没进 .gitignore 被提交 —— 密钥永久留在 Git 历史。现状：已忽略。
  3. 截图、作业文档中出现明文 Key —— 提交后等于公开。现状：均已脱敏。

任务三 · 多平台热切换（工程思维）

页面「模型」下拉同时列出硅基流动（Qwen2.5-7B / DeepSeek-V4.1-Flash / GLM-5.3-Flash）与七牛在线客服（conatus-free），切换后可直接对话，后端按模型 id 自动路由到对应平台。

  1. 为什么 Key 不能放前端？前端代码原样下发，任何人查看源码或抓包都能拿走 Key；Key 只能在服务端 .env，浏览器只访问同源的 /api/ai/*。
  2. 多轮对话为什么要把历史消息一起发？大模型接口无状态，每次请求独立；前端维护 messages 数组（system + 历次 user/assistant），每次整体提交。
  3. 换个平台改哪几个值？改 AI_PROVIDER、该平台的 BASE_URL、API_KEY 和模型 id。因为各家都遵循 OpenAI 兼容协议，请求体、返回结构与错误格式一致。
